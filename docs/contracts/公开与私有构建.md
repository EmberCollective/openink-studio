# 公开与私有构建

2026-10-28：私有主线保存完整开发资料，通过显式构建开关区分功能，通过导出区分公开范围。两版共用主代码，不维护私有功能分支，不反复 merge。

## 仓库与资料边界

用户已授权私有开发仓库包含逆向工具、逆向资料、`fonts/` 样本和 `private/gfont/`，供多机协作；此授权替代旧的“私有资料不入库”规则，**不授权公开这些内容**。

| 范围 | 公开源码 | 私有开发仓库 |
| --- | --- | --- |
| SVG、PDF、图片、普通字体、自建中心线字库 | 支持 | 支持 |
| 原版 gfont v1–v5、V5 TEA 解密 | 无实现、无可用入口 | 显式启用 `openink-gfont` 库 |
| 原厂字体样本、逆向工具与证据、厂商密钥 | 严禁导出 | 按用户授权保存 |
| `docs/bugs/` | 整个目录排除 | 保留缺陷与验证记录 |

组织 `EmberCollective`，公开仓库名 `openink-studio`，私有仓库名 `openink-studio-private`。2026-10-28 用户已授权创建远端并推送这两个源码仓库，覆盖此前仅本地整理的限制。两个本地交付目录为 `.cache/private-source-0.4.3` 与 `.cache/public-source-0.4.3`，各自使用独立 `main` 仓库，并且只能关联对应可见性的远端。公开版从全新单提交历史开始；私有版包含授权的开发资料。构建输出和检查明细留在 `.cache/`，不加入源码提交。README 保留供用户后续修改。

## 默认与私有构建

`private/gfont/` 是私有 Rust crate，包含原字体解析、TEA 解密与排版，使用公开的 `desktop/model/` 几何类型。主程序通过 `private-gfont` 可选依赖启用它，界面根据后端实际能力显示入口。默认构建关闭此功能；公开导出还会移除私有依赖声明，无需私有目录即可解析 Cargo 项目。

```powershell
# 默认构建，无 gfont 功能
powershell -ExecutionPolicy Bypass -File desktop/dev.ps1
powershell -ExecutionPolicy Bypass -File desktop/build.ps1

# 私有构建，同一份主线代码
powershell -ExecutionPolicy Bypass -File desktop/dev.ps1 -PrivateGfont
powershell -ExecutionPolicy Bypass -File desktop/build.ps1 -PrivateGfont
```

`desktop/src/legacy_font.rs` 仅为迁移备份，不参与编译。公开版可继续编辑私有版工程里已有的笔迹；原版字体设置保留并提示改选普通字体或自建字库，生成新的 gfont 笔迹会被拒绝，不删除已有素材。

## 转换依赖

Windows 开发需 Node.js、Rust stable 及对应 C/C++ 构建工具、WebView2 Runtime、Python 3。启动脚本安装 npm 依赖；图片/PDF helper 依赖需另行安装：

```powershell
python -m pip install -r desktop/helpers/requirements.txt
```

该清单包含 Pillow、PyMuPDF、NumPy 与 OpenCV。PDF / PNG 中心线提取另需 AutoTrace；Windows 下自行安装 `autotrace.exe` 并放入 PATH，或在设置面板指定可执行文件路径。Python 路径也可在设置面板配置。缺少 AutoTrace 会导致线路提取失败；照片拉平与横线识别并不能替代线路提取。命令行串口工具另需 `pyserial`。运行时不会联网下载转换器。

## 导出独立公开树

```powershell
# 正式导出：指定已提交快照，目标目录必须尚不存在
python tools/export_public.py --ref HEAD --output .cache/public-source-0.4.3 --init-git

# 包含未提交改动的本地预览，使用另一个不存在的目标目录
python tools/export_public.py --worktree --output .cache/public-source-preview-0.4.3 --init-git
```

导出依次执行 `git archive` / `.gitattributes` 的 `export-ignore` 筛选、删除私有 Cargo feature／依赖及锁文件条目、检查禁止文件与密钥／解密声明。`--worktree` 先建立临时快照，不修改开发仓库索引。`--init-git` 在输出目录建立一个全新根提交，不配置 remote、不推送，也不复制私有开发历史。

公开树必须排除逆向资料、工具、原厂字体、私有库、整个 `docs/bugs/` 及开发环境缓存。`.gitignore` 管理临时文件；公开边界由 `.gitattributes` 和导出检查共同维护，不能用“被 Git 跟踪”判断某文件可公开。

## 后续更新公开仓库

继续在私有主线开发。每轮从指定快照导出到新的空目录，检查导出内容，再将源码同步到公开仓库的工作树，提交到公开仓库自己的历史。

- 保留目标公开仓库的 `.git`，不复制私有仓库或导出临时仓库的 `.git`。
- 同步前确认公开工作树无未保存改动；同步时同时核对已删除文件，避免旧私有文件残留。
- 在公开仓库检查差异、禁止内容和构建，再按用户授权提交、push；无需合并私有主线历史。

导出脚本拒绝覆盖已有目录。不要把私有仓库设为公开，也不要把其 remote 改指公开仓库。当前只准备源码，不发布安装包；二进制组合分发的许可证边界见根 README。

## 验证入口

本地拆分已完成公开树独立前端构建、无私有库的 `--locked --all-features` 测试、私有字体库测试、禁止内容及独立 Git 历史检查。后续更新可用以下入口复核；导出目标必须选择尚不存在的新目录：

```powershell
python -m unittest discover -s tests -p test_public_export.py -v
npm.cmd --prefix desktop/ui run build

# 在不带 private/ 的公开导出目录执行
cargo test --manifest-path desktop/Cargo.toml --locked --all-features

# 在具备私有源码的开发目录执行
cargo test --manifest-path private/gfont/Cargo.toml
cargo test --manifest-path desktop/Cargo.toml --features private-gfont
```

公开树需另查文件清单、禁止内容和独立 Git 历史。只在开发目录关闭 feature 不能证明独立构建成立；React/jsdom 离线测试也不能替代实际桌面视觉与实机验收。
